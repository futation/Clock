# 开发踩坑记录

Clock 在开发过程中踩过的坑与最终采用的方案，给想复刻或改造的读者参考。全部经验都来自 `clock.py`（约 870 行）这一个文件，可对照阅读。

## 1. 无边框窗口：原生 Win32 方案，不是 overrideredirect

自定义标题栏最常见的做法是 `root.overrideredirect(True)` 再自己画拖拽。这条路放弃得很快：假窗口没有任务栏项、没有阴影、不能 Aero Snap、不能边缘缩放，最大化后还会盖住任务栏。

最终方案与微信/Chrome 相同——**保留原生窗口，拦截消息把非客户区"藏"起来**：

1. 用 comctl32 的 `SetWindowSubclass` 给顶层窗口装子类过程；
2. `WM_NCCALCSIZE`（wparam 为真时）直接返回 0，让客户区铺满整个窗口，系统标题栏就没了；最大化时按边框厚度缩进，避免内容被裁；
3. `WM_NCHITTEST` 按坐标返回 `HTCAPTION`（标题栏带）或四角/四边的边缘码，系统原生拖拽和缩放就都回来了。

**关键坑：子类装好后必须 `SetWindowPos(SWP_FRAMECHANGED)` 强制重发一次 `WM_NCCALCSIZE`。** 窗口往往在子类安装前已经映射、错过了首次 `WM_NCCALCSIZE`，不补这一刀系统标题栏去不掉。

## 2. 命中透传链：窗口"能看不能拖"的元凶

tkinter 的客户区不是一整块——它被 `TkChild` 子窗口层层覆盖。真实鼠标的命中测试先落在子窗口上，根本到不了顶层窗口的 `WM_NCHITTEST`。表现为：窗口显示正常，但标题栏拖不动、边缘缩不了。

解法是给**根 TkChild**（`GetParent` 前的 `winfo_id()` 那层）也装一个子类过程，在标题栏带/缩放边缘带返回 `HTTRANSPARENT`，命中就穿透到顶层窗口处理。此外再把标题栏 Frame、标题 Label、主 Frame 这几个纯展示控件各自子类化为无条件 `HTTRANSPARENT`，让标题栏整条带子（包括按钮之间的空白）都能拖。**动命中测试相关代码时，这条链上任何一环断了，窗口立刻变回"能看不能拖"。**

## 3. ctypes 回调的两个坑

- **wparam/lparam 必须声明为 `c_void_p`**。用 `c_size_t`/`c_ssize_t` 时，部分消息的参数值超出其表示范围，回调直接抛 `OverflowError`，而且被 try/except 吞掉后表现为"拦截整体失效"，非常隐蔽。
- **已存在的 HWND 实例不能再包一层 `wintypes.HWND(x)`**（Python 3.12 抛 TypeError）；传 `None` 时则必须写 `wintypes.HWND(None)`，裸 `None` 过不了 argtypes 校验。

另外回调对象（`WINFUNCTYPE` 实例）要存成实例属性防止被垃圾回收，否则子类过程指向已释放的函数，进程直接崩。

## 4. DPI 感知

- `main()` 开头 `SetProcessDpiAwareness(2)`（PER_MONITOR_DPI_AWARE），高分屏下窗口原生渲染不模糊；失败回退 `SetProcessDPIAware()`。
- tk 8.6.9+（Python 3.8+）默认进程级 DPI 感知，此后 tk 像素 ≈ 物理像素，窗口/字号换算都要按实际 DPI 来。
- **字体自适应公式要用 96DPI 等效高度**：先 `h96 = 高度 × 96 / dpi` 再套 `字号 = min(h96//5, 宽96//6)`。直接用物理像素套公式会跟 DPI 二次相乘，125% 缩放下字号大出一圈。
- **写测量脚本时，测量进程自己也要先开 DPI 感知**，否则 `GetWindowRect` 返回虚拟化坐标——125% 屏上所有尺寸缩小 0.8 倍，得出的结论极具迷惑性。

## 5. 窗口尺寸与缩放防抖

- `grid_propagate(False)` 冻结几何传播，让字体自适应不再反向推动窗口大小（否则拖动缩小时字体与窗口互相推挤，大数字一直抖）。**它必须在 `winfo_reqwidth` 测量之后执行**，顺序颠倒了窗口会按初始内容的请求尺寸打开，变成一小颗。
- 最小窗口尺寸用 96DPI 逻辑像素定义，运行时乘缩放系数；宽度方向有系统边框修正（实测约 ×1.30/单位，高度约 ×1.25/单位），跨机器换算时留意。
- 字号没变化就不重绘（`_last_font_size` 缓存），拖动过程中避免无谓重绘带来的抖动。

## 6. 三模式状态机

倒计时 / 正计时 / 闹钟共用一套按钮，核心是进入/离开每个模式时输入栏与大屏的同步规则，以及**实时时钟 tick 的显式生命周期管理**（`_start_clock_tick` / `_stop_clock_tick`，而不是"每帧判断该不该刷新"的条件式）：

- 倒计时：进入时恢复记住的输入并与大屏同步；切走时保存
- 正计时：进入时输入栏与大屏同时清零
- 闹钟：进入时大屏刷新为当前时间并走实时时钟；按开始后切换为剩余时间倒计时；触发或重置后回到走时钟状态

条件式刷新在这套交互下会出现"大屏该走时钟时卡住"或"重复调度 tick"的怪现象，显式启停虽然多几行代码但状态永远可预期。

## 7. 打包

PyInstaller 单文件模式（`--onefile --windowed`）运行时解压到临时目录，图标资源路径要用 `sys._MEIPASS` 兼容（源码运行时回退 `__file__` 所在目录），配合 `--add-data "Clock.ico;."` 打进去。窗口图标加载失败不应致命——整体包 try 即可。

## 8. 其他

- ico 文件的帧顺序：Pillow 自带的 ico 保存固定从小到大写帧，而 Windows 照片查看器显示第一帧，放大看就糊了。`img2ico.py` 手动写 ICO 结构、帧从大到小排列，预览即清晰大图（Windows 取用图标按尺寸挑帧，不受顺序影响）。
- 非 Windows 平台不要硬编码 return：Win32 初始化失败时回退系统标题栏 + 复选框置顶，程序在 Linux/macOS 上也能跑（响铃也做了三平台分支）。
